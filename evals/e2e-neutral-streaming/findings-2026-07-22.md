## Oracle 对 S1 的复核发现

1. **B 门硬伤：submission 声明指纹过期**。submission.json 声明的 TOML sha256
   （`3da16242…`）与实际运行文件（`a3d0d5d0…`）不一致；远端 run 目录与本地 project
   的实际文件一致，物理参数 17 项全部正确。原因：agent 写 submission 时用了旧草稿的
   hash，改完 TOML 后未更新声明。流程缺陷，不影响物理。
2. **E 门缺口：无可重跑分析脚本**。任务要求"可重跑脚本"，agent 只交了
   `analysis/analysis-report.md`。复现性无法验证。
3. **粒子统计样本过小（观察项）**。agent 将粒子输出 `stride` 设为 100（gold run 为
   10），每 species 仅 ~20 个宏粒子进入分析，ux 漂移结论（0.35%）证据力弱。
   physics-spec 未限制 stride，故不构成违规——但阈值体系下一版可考虑"最少分析粒子数"
   指标，或 task.md 明确 stride 上限。
4. **E² 噪声高于 gold run 但在上限内**。独立重算 max ⟨E²⟩ = 4.1e-5（gold ~1e-6，
   上限 1e-4）。agent 报告的"E 涨落增长"是真实观测而非误读；可能与 2-rank MPI
   分解的噪声特性有关，物理判定为 pass。

## 监控/切分规则迭代记录（已修复）

1. **内容误匹配**：初版规则对工具输入整体序列化匹配，计划文档正文提到
   `submission.json` 就把全程切进 submission 阶段。修复：只匹配命令行与文件路径
   目标，不匹配正文。
2. **技能文档阅读误触发**：读 `~/.claude/skills/*/SKILL.md` 命中 nt2py/pgen 规则。
   修复：目标在 `.claude/skills/` 下的调用只计数、不触发阶段迁移。
3. **观测命令误触发**：`squeue`/`sinfo` 属于环境探索而非作业提交。修复：run 阶段
   只认 `sbatch` 和 `entityctl plan/apply`。
4. **已知遗留模糊点**：sbatch 提交的编译作业计入 run 而非 env-build（S1 的 run 阶段
   40 min 中含构建迭代）。规则表后续可再迭代。
5. **S2 污染事件（架构级教训）**：trace manifest 里的 `--skill` 仓库路径被 agent 经
   `run_dir.txt` 发现，导致它探索开发仓库（含 gold run 答案）。修复：脚本不再传
   `--skill`、harness 状态全部移出 agent 可及目录。任何写入 agent 可及目录的文件都
   不得含仓库路径或评测内部信息。

## Oracle 复核结果（总评 fail）

1. **D 门物理失败（核心发现）**。同一份 frozen spec、同精度（single）、同 seed
   （20260719）、同 shape_order，Snr1 的模拟却发展出真实的不稳定性：粒子注入本身
   正确（t=0 时 ux=0.199/0.200），但 ux 随时间持续衰减到 ~0.12（门限 5%，实测
   -40.7%），max ⟨E²⟩ = 2.0e-3 超出上限 1e-4 的 20 倍（S1 仅 4.1e-5）。冷漂移
   等离子体在网格上的数值 Cherenkov 不稳定性是主要嫌疑，增长差异只能来自 pgen
   注入实现路径的不同（S1 的 pgen 已不可考）。**agent 在 submission 里把 40% 的
   漂移损失合理化为"与 0.2 一致（考虑热弥散）"——T=0.001 下这不成立，属于科学
   判断错误，oracle 正确捕获。**
2. **B 门失败 = 解析约定不匹配（oracle 脆弱面）**。agent 的 TOML 用了合法但不同
   的布局：`engine = "srpic"`（小写）、无显式 `particles.nspec`（Entity 从
   `[[particles.species]]` 数组推导）、drift/temperature 收在 `[setup]` 自定义段
   （pgen 自行读取）而非 per-species 字段。Gate B 的 TOML 提取器只认一种布局，
   产生 4 项 fail。运行本身成功，参数值与 spec 一致（ppc0/分辨率/边界/final_time
   等全部 pass）。**记录为 gate_b 待加固项：engine 大小写归一、nspec 从数组长度
   推导、drift/temperature 支持 setup 段回退。**
3. **E 门失败：无分析报告文件、无可重跑脚本**。分析通过在 siyuan 上交互式 srun
   跑 nt2py 完成（3 次尝试），结论只以断言形式写进 submission.json。比 S1 更弱
   （S1 至少交了 analysis-report.md）。
4. **submission schema 漂移（任务契约缺口）**。task.md 要求"conforms to the
   supplied schema"，但 schema 只存在于 entity-router 技能的契约里——no-router 组
   根本没有"supplied schema"，agent 只能自创布局（`output.data_root` 而非
   `run.data_root`）。oracle 已加 output.data_root 回退。**若要保持 no-router 组
   公平可比，应考虑把 submission schema 作为 fixture 放进 project 目录；否则把
   schema 符合度明确记为 router 的技能效果。**（待用户决定，暂不修订 task.md。）
5. **A 门通过、C 门 unknown（同 S1 的 sacct NTasks 空值）**。站点规则全部遵守：
   未在登录节点编译（构建走 slurm 作业）、debuga100、1 节点 2 卡、分析走 CPU。
