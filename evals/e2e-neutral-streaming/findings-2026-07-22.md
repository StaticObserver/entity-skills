## Oracle review findings for S1

1. **Gate B hard failure: the fingerprint declared in submission.json is stale**. The TOML sha256
   declared in submission.json (`3da16242…`) does not match the file actually run
   (`a3d0d5d0…`); the remote run directory matches the actual file in the local project,
   and all 17 physics parameters are correct. Cause: when writing the submission the agent
   used the hash from an old draft and did not update the declaration after editing the
   TOML. A process defect; the physics is unaffected.
2. **Gate E gap: no re-runnable analysis script**. The task required a "re-runnable
   script"; the agent only delivered `analysis/analysis-report.md`. Reproducibility
   cannot be verified.
3. **Particle statistics sample too small (observation item)**. The agent set the particle
   output `stride` to 100 (gold run: 10), so only ~20 macroparticles per species entered
   the analysis, leaving the ux drift conclusion (0.35%) weakly supported. physics-spec
   does not limit stride, so this is not a violation — but the next revision of the
   threshold system could consider a "minimum number of analyzed particles" metric, or
   task.md could state an explicit stride ceiling.
4. **E² noise higher than the gold run but within the cap**. Independent recomputation:
   max ⟨E²⟩ = 4.1e-5 (gold ~1e-6, cap 1e-4). The agent's reported "E fluctuation growth"
   is a genuine observation, not a misreading; it may relate to the noise characteristics
   of the 2-rank MPI decomposition. Physics verdict: pass.

## Monitoring / segmentation rule iteration record (fixed)

1. **Content false-matching**: the initial rules serialized the entire tool input for
   matching, so a plan document mentioning `submission.json` in its body text cut the
   whole session into the submission phase. Fix: match only command lines and file-path
   targets, not body text.
2. **Skill-document reading false trigger**: reading `~/.claude/skills/*/SKILL.md` hit
   the nt2py/pgen rules. Fix: calls whose target is under `.claude/skills/` are counted
   but do not trigger phase transitions.
3. **Observation-command false trigger**: `squeue`/`sinfo` are environment exploration,
   not job submission. Fix: the run phase recognizes only `sbatch` and
   `entityctl plan/apply`.
4. **Known remaining ambiguity**: sbatch-submitted build jobs count toward run rather
   than env-build (S1's 40 min run phase contains build iterations). The rule table can
   be iterated further later.
5. **S2 contamination incident (architecture-level lesson)**: the `--skill` repository
   path in the trace manifest was discovered by the agent via `run_dir.txt`, leading it
   to explore the development repository (which contains the gold run answers). Fix:
   scripts no longer pass `--skill`, and all harness state was moved out of
   agent-reachable directories. No file written into an agent-reachable directory may
   contain repository paths or evaluation-internal information.

## Oracle review results (overall fail)

1. **Gate D physics failure (core finding)**. With the same frozen spec, same precision
   (single), same seed (20260719), and same shape_order, Snr1's simulation nevertheless
   developed a genuine instability: particle injection itself was correct (ux=0.199/0.200
   at t=0), but ux decayed continuously to ~0.12 over time (gate 5%, measured -40.7%),
   and max ⟨E²⟩ = 2.0e-3 exceeded the 1e-4 cap by 20× (S1 was only 4.1e-5). Numerical
   Cherenkov instability of a cold drifting plasma on the grid is the prime suspect; the
   growth difference can only come from a difference in the pgen injection implementation
   path (S1's pgen is no longer recoverable). **The agent rationalized a 40% drift loss
   in the submission as "consistent with 0.2 (given thermal spread)" — at T=0.001 this
   does not hold; it is a scientific judgment error, correctly caught by the oracle.**
2. **Gate B failure = parsing-convention mismatch (oracle fragility)**. The agent's TOML
   used a legal but different layout: `engine = "srpic"` (lowercase), no explicit
   `particles.nspec` (Entity derives it from the `[[particles.species]]` array), and
   drift/temperature collected in a custom `[setup]` section (read by the pgen itself)
   rather than per-species fields. Gate B's TOML extractor recognizes only one layout,
   producing 4 fails. The run itself succeeded, and the parameter values matched the spec
   (ppc0/resolution/boundaries/final_time all pass). **Recorded as gate_b hardening
   items: normalize engine case, derive nspec from the array length, support a setup-
   section fallback for drift/temperature.**
3. **Gate E failure: no analysis report file, no re-runnable script**. The analysis was
   done via interactive srun running nt2py on siyuan (3 attempts); conclusions were
   written into submission.json only as assertions. Weaker than S1 (S1 at least delivered
   analysis-report.md).
4. **Submission schema drift (task-contract gap)**. task.md requires "conforms to the
   supplied schema", but the schema exists only in the entity-router skill's contract —
   the no-router group simply has no "supplied schema", so the agent could only invent
   its own layout (`output.data_root` instead of `run.data_root`). The oracle has added
   an output.data_root fallback. **To keep the no-router group fairly comparable,
   consider placing the submission schema into the project directory as a fixture;
   otherwise explicitly record schema conformance as a router skill effect.** (Pending
   user decision; task.md not revised for now.)
5. **Gate A pass, Gate C unknown (same sacct NTasks empty value as S1)**. All site rules
   were followed: no compiling on the login node (builds went through slurm jobs),
   debuga100, 1 node 2 GPUs, analysis on CPU.
